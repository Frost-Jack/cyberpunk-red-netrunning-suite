АКТУАЛЬНЫЙ РУЧНОЙ ПРОГОН ПОСЛЕ АУДИТА, 24.10.2026

ЭТИ СЦЕНАРИИ НЕ ВЫПОЛНЕНЫ В ЖИВОЙ FOUNDRY. Автотесты ниже используют
имитацию Foundry I/O и отдельный Chrome/WebGL. Проводить сценарии в копии
мира с Foundry12.343/CPR0.92.4; нужны GM, второй GM, player и spectator.
После обновления файлов перезагрузить клиенты, чтобы зарегистрировались
новые settings/imports/templates. Версия модуля остаётся1.1.

GM
G1. Открыть кнопку «Кастомный NET-контент» (иконка file-pen в верхней строке).
Создать Program, Black ICE и Demon с нуля, затем из native world образцов.
Изменить имя/картинку/статы/урон/цену/слоты/цели/стоимость/лимит/visual/effects.
Save создаёт только определение. В Actors/Items и персонажах ничего не меняется.
G2. Нажать «Создать документ Foundry», отменить: документов0. Подтвердить и
быстро повторить: один диалог/один новый world Item program или Actor
blackIce/demon. Нативный лист открывается; документ не установлен персонажу.
G3. Скопировать определение: ID новый. Export/import JSON: новый draft,
сохранение явное. Импорт JavaScript damage/eval или unknown effect отклоняется.
Manual effect сохраняется только текстом. Изображение из произвольной
относительной папки Data разрешено; javascript: и ../ не разрешены.
G4. Во время Save/Create/Delete нельзя заменить draft. Закрытие с несохранёнными
правками запрашивает отмену правок; отказ сохраняет окно. Обычный update мира
не сбрасывает fields/scroll/size редактора.
G5. Добавить custom ICE/Demon через picker архитектуры. Save, Duplicate,
Export, удалить library definition, Import: native stats/effects/visual и
stable custom ID сохраняются. Вновь созданные экземпляры имеют новые UUID.
Существующие Actor/Item не обновляются автоматически вслед за библиотекой.
G6. Переименовать custom Sword/Killer/Imp в native sheet: не получают чужие
RAW эффекты из одного имени. Native class остаётся источником класса,
custom targets ограничивают его подмножество; межклассовые атаки ручные.
G7. Два активных GM одновременно тратят действия: обе траты сохраняются,
Actor создаётся один раз. Повторная доставка того же запроса не дублирует его.
G8. Добавить рядом личного Actor и legacy немаркированного ICE; удалить
архитектуру: удаляется только managedEntity temporary Actor. Личные/legacy
документы и занятая/немаркированная папка сохраняются. Нужную ручную очистку
старых сущностей выполнить самому после проверки происхождения.
G9. Выбрать горящего/disabled раннера целью. Отдельно снять только огонь:
deckDisabled остаётся. Снять deckDisabled: native module flag очищен.
HP/REZ меняются явной командой; destruction отличается от 0REZ.
G10. Оборудование: Function Driver привязать к exact programId; Super Slide
к installed active Speedy/Worm; Netsuit Insulation к equipped suit;
FBC Hardware установить внутрь coating. Проверить shared pool, limits и
отсутствие второго native AE. Настройка flags указана в EQUIPMENT-REVIEW.txt.
G11. Backup при полной деке не восстанавливает часть списка; Phoenix чинит
только destroyed данного забега после safe Jack Out; Smithy не конвертирует
уничтоженный tombstone. Для Training+Range GM каждый раз выбирает2м/8м.
G12. Deferred defense/SPEED: отменить native roll, повторить; удалить/отключить
цель, пока открыт диалог. Старый результат не применяется, повторов карточек0.

G13. В native sidebar удалить сначала backing ICE/Demon, затем embedded
Program и отдельного runner Actor. Исчезают только соответствующие сущности,
цели/привязки/ожидающие тесты; чужие документы не затронуты. Если удалён
backing ICE, surviving Item выключается; повторить со снятой кибердекой.

ИГРОК
P1. Есть явный acting runner и текущая цель; длинные имена не меняют ширину
колонок. Недоступные действия приглушены с причиной в tooltip, без серии
уведомлений. Стоимость custom activation видна на кнопке.
P2. Две копии одной custom программы: независимый round/run allowance;
custom стоимость2 списывается один раз. Отмена native roll возвращает2,
успех завершает Attacker. Переименование не меняет цели/лимит/visual/effects.
P3. Выбрать программу/ICE неподходящего класса или этажа: action не тратится.
Custom ICE с target subset Black ICE не устраивает засаду обычному Booster.
P4. Scout бесплатный Pathfinder сразу после Jack In. После другого NET/Meat
действия или перемещения бесплатного Pathfinder уже нет. Reconnect не
возвращает истраченное окно. Чистая отмена Attacker/Swifty не тратит окно.
P5. Super Slide разрешает две завершённые попытки за Turn. Пока первая
ожидает броска, вторая не резервируется. Третья запрещена; новый ход сбрасывает
лимит. Без upgrade действует одна попытка.
P6. Jack Out теряет принадлежащие игроку Control Nodes. Повторное Jack In
не возвращает их без проверки. Узел другого игрока сохраняется.
P7. Пока союзник подключён, взломанные пароли остаются. После выхода последнего
раннера breached/control сбрасываются, Virus/Cloak сохраняются. REZ/позиции
и влияние persistent Virus GM проверяет вручную, без слепого auto-restore.
P8. 3D: pan после yaw/tilt; выбор T/ПКМ; genuine target facing, Actor/Token art;
кастомные model/color/FX. 9 мини-программ -> autoderez Attacker ->8: атака
продолжается. Hit/miss ждёт результата защиты и не меняет HP/REZ сам.
P9. Пока FX активен, включить reduced motion или скрыть цель туманом:
эффект прекращается. Удалить hovered/queued selected entity: T/отложенный
клик не используют старую ссылку. В покое постоянных кадров3D нет.
P10. Начать resize нижней панели и закрыть/перерисовать окно: cursor/body
возвращаются, window listeners не остаются. Камера/scroll/size не сбрасываются
обычными обновлениями. Проверить480px,780px,длинные RU имена и клавиатуру.

НАБЛЮДАТЕЛЬ
S1. Наблюдать выбранного союзника на развилке: видимость точно его, без знаний
соседней ветки. При запрете наблюдения видна причина.
S2. Сменить союзника/архитектуру согласно spectatorFreeMove; выйти: свой runner
возвращается неизменным. Если союзник отключается, чужой runner не подставляется.
S3. Нельзя тратить действия, менять HP/REZ/effects или создавать content.
Кнопка редактора GM отсутствует. Обычные запреты повторно проверяются GM-side.
S4. Чужая атака в скрытой ветке не раскрывает её через FX/HUD/частицы.
Доступность данных через browser console отдельно признана ограничением
world settings: этот тест подтверждает UI fog, а не серверную секретность.

ИСТОРИЯ ПРЕДЫДУЩИХ РУЧНЫХ СЦЕНАРИЕВ

NETRUNNING SUITE — РУЧНАЯ ПРОВЕРКА В FOUNDRY V12
24.10.2026. Автотесты не заменяют эти проверки двумя клиентами.

ПОДГОТОВКА
Сделайте резервную копию мира. Откройте мир как GM и отдельным браузером как
игрок. Назначьте игроку его Actor с экипированной кибердекой и активной ролью
Interface. Установите разные копии Sword, Armor, Shield и один Black ICE.
GM создаёт архитектуру: вход -> пароль -> развилка; одна ветвь длиннее другой.
Добавьте файл, Control Node, демона и несколько разных Black ICE.

ИНТЕРФЕЙС И ВИДИМОСТЬ
1. GM: подключить игрока. Игрок: увидеть вход и только известные этажи.
2. Оба: открыть справочник, прокрутить до оборудования и Rock Lobster.
   Текст читается без наложений; группы отделены, изображения программ берутся
   из доступных компендиумов. Программы установленной деки выделены рамкой.
   Переключить «Каталог»/«Правила», прочитать блок про очередь инициативы.
   Переключение доступно стрелками клавиатуры; выбранная вкладка сохраняется.
3. Навести на лёд и программу: эффект в подсказке; карточка не подпрыгивает.
4. Зритель без деки: «Наблюдать» -> союзник. Видимость совпадает с выбранным
   союзником. Выход из наблюдения возвращает к своему раннеру, не удаляя его.
5. GM: свернуть файловую панель и панель раннеров. Архитектура занимает
   освободившееся место, нижняя панель не меняет высоту от выбора/таргета.

3D
6. Переключить 2D/3D от GM и игрока. Даже со старым кешированным manifest
   3D-стили должны подгрузиться. Не должно быть огромного необрезанного токена.
7. В 3D видны настоящие изображения Actor/Token; демон стоит отдельно слева
   от собственного этажа, а не в ряду программ. Связи ветвей не меняются.
8. GM: ЛКМ выбрать раннера/лёд, T или короткий ПКМ назначить цель,
   двойным ЛКМ открыть лист Actor. Действия выполняются выбранной сущностью.
9. Камера: колесо — масштаб; ЛКМ по пустому месту — поворот в 3D;
   Shift/средняя кнопка/ПКМ с перетаскиванием — сдвиг. ПКМ-перетаскивание
   не должно одновременно назначать цель. Повторить в 2D для сдвига камеры.
10. GM: выбрать раннера, нажать переход на другой этаж в 3D. Игроку доступны
    только соседние переходы. Проверить неизвестную ветвь и блокировку пароля.
11. Выбрать цель, свернуть/открыть окно 20 раз. Камера не сбрасывается,
    события не дублируются; после закрытия нет новых ошибок в консоли.

ПРОВЕРКИ И ДЕЙСТВИЯ
12. Backdoor против DV10: итог10 не взламывает, итог11 взламывает.
    Встречная проверка при равенстве выигрывается защищающимся.
13. Pathfinder на текущем невзломанном пароле с DV выше результата:
    за паролем ничего не раскрывается. На развилке блокируется только её ветвь.
14. Одну копию Sword нельзя активировать дважды за раунд, другую — можно.
    Jack Out/In и повторное подключение в том же раунде лимит не обходят.
15. Attacker запускается атакой за одно NET-действие и деактивируется после
    применения независимо от наличия броска урона. Отмена диалога возвращает
    резерв действия. Проверить попадание и промах.
16. Armor/Shield/Flak: только одна активная копия каждого названия;
    использованная копия Defender недоступна до нового забега. Аналогично
    одноразовый Superglue. Другие неиспользованные копии доступны.
17. GM атакует программу игрока. Игрок получает обычный диалог DEF+1d10,
    без Interface, с нативными опциями. Защита самого раннера — Interface+1d10.
18. Обычный урон до 0 REZ: Derezzed, нельзя атаковать этой программой;
    выключение/повторное включение разрешено с учётом лимитов. Урон Dragon,
    Killer, Sabertooth с корректным источником: Destroyed. GM может восстановить.
19. Anti-program лёд не провоцируется раннером без активных программ.
    При активной программе цель эффекта — случайная активная программа.
    После начала преследования выключение программ само по себе лёд не снимает.
20. Slide доступен один раз за ход. Успех отвязывает лёд и перемещает ровно
    на выбранный соседний этаж; пароль по-прежнему препятствует спуску.
21. Ручной Rez Black ICE в бою с целью ставит лёд в очередь БЕЗ бесплатной
    засады/SPEED TEST. Ловушка разрешена только вне боя; засада имеет SPEED TEST.
    Число инициативы льда равно максимуму, но лёд сортируется выше.
22. Control Node активируется один раз за ход; Scanner — мясное действие,
    несовместимое с NET Actions этого хода. Virus требует настроенных GM DV
    и количества действий на дне самой длинной ветви; итог становится DV удаления.

ОБОРУДОВАНИЕ
Оборудование должно быть именно установлено в используемую деку, не лежать
свободно в инвентаре. Если предмет переименован и не распознаётся, GM может
задать flags.cyberpunk-red-netrunning-suite.equipmentKey каноническим ключом
из scripts/reference-catalog.js. Ограничения слотов/классов проверяются при Rez.

23. Hummingbird: +1 NET Action; Training/MicroMate: двойной прямой урон мозгу.
24. Scout: бесплатный первый Pathfinder после Jack In. Warrior: бесплатный
    установленный неиспользованный Armor. Kestrel 2: до двух разных Speedy.
25. Swifty Clean: два обычных Cloak-броска за одно действие, лучший результат;
    повторный Cloak с этим оборудованием за тот же забег запрещён.
26. Defense Sequencer: потерять активный Armor; в начале следующего хода
    включается другая неиспользованная Armor без NET Action. Не сразу при потере.
27. GM: выбрать раннера целью -> «Применить особый эффект».
    Insulated Wiring предотвращает Ignite, KRASH Barrier — принудительный
    Jack Out, Hardened Circuitry — ЭМИ/отключение не-ICE программой.
    Без защиты: огонь наносит 2 HP в конце хода; погасить — мясное действие.
28. Snaketrap: первое случайное уничтожение (Asp/Poison) предотвращается;
    второе — нет. Backup Drive: восстановить сохранённую не-ICE программу
    мясным действием, не сбрасывая её ограничения использования.
29. Phoenix: безопасный Jack Out восстанавливает уничтоженные программы;
    обычное небезопасное отключение этого бонуса не даёт. Kirama делает его
    безопасным. Учитывайте ручную кнопку GM восстановления отдельно.
30. Bushido: Killer SPD +2 за каждый ускоритель. Swamp Mist: Wisp 2d6.
    Feline Instinct: конкретный Sabertooth после уничтожения получает +1d6;
    Hangry Dragon восстанавливает REZ после уничтожения. Aerie меняет
    дерес Raven на уничтожение выбранного случайного Defender.
31. Smithy: мясным действием одновременно меняет все Sword/Banhammer,
    сохраняет их itemId и историю использования. Запрещённые декой результаты
    не допускаются. CyberConductor переключает только связанные деки,
    дересает активные программы до REZ 0 без лечения и не разделяет оборудование
    между деками. При возврате к исходной деке их надо выключить и включить заново.
    Обычный переключатель наносит 3 HP, Integrated — 0.
32. Combat Recorder: другой раннер проваливает нативный Death Save в той же
    архитектуре. Создаётся обезличенная запись; 50 eb автоматически не начисляются.

ГРАНИЦЫ АВТОМАТИЗАЦИИ
Дальность 2/6/8 м, стены, доступ к физической точке, ДНК-ключ и DV17 проверяет GM:
в архитектуре нет модели физических точек доступа. Продажа записей, часовая
установка программ, совместимость тела FBC и предметов с персонажем не выполняются
автоматически. Обычные строки справочника — не команда создать предмет.
Going Quiet — опциональная система, автоматически не включена.
3D — альтернативный вид, не отдельный источник игровых правил.

ОБЪЁМНЫЕ МОДЕЛИ И КОМПАКТНЫЙ СПРАВОЧНИК

33. GM: включить 3D на заполненном этаже. Проверить кобру Asp, волка
    Hellhound, самурая Killer, дракона, демона на отдельной площадке слева.
    Изображения Actor/токенов остаются в подписях. RockLobster показан как
    вариант Balron; его внешность в книге не определена, это интерпретация.
34. Повернуть и приблизить камеру. Модели стоят НА площадках, дальние модели
    закрываются непрозрачными этажами. Подписи остаются читаемыми и неподвижны
    при наведении. ЛКМ выбирает, T/короткая ПКМ задаёт цель, двойной клик GM
    открывает Actor. Проверить обычную программу и Black ICE игрока отдельно.
35. Удерживая ПКМ, переместить камеру; цель не должна меняться. Сразу нажать
    кнопку поворота: достаточно первого клика. «Вход» возвращает стартовый вид.
    Переключить 2D/3D и изменить размер окна: не должно быть пустого экрана.
36. Игрок и наблюдатель: 3D показывает только доступные им этажи и программы,
    скрывает DV и содержимое неизученных ветвей так же, как 2D.
37. Справочник: категории раскрыты списком, без сворачивания. Поиск «Sword»,
    «броня», «удача», «Pathfinder» фильтрует карточки без потери фокуса.
    Проверить очистку, отсутствие результатов, сохранение запроса после рендера.
38. Вкладка «Правила»: краткие пункты, схемы и примеры с числами; таблицы
    действий и бросков читаются без мелкого шрифта. При ширине меньше 900 px
    карточки идут одной колонкой. Escape закрывает только справочник.
39. ПКМ-pan: потянуть карту вверх, вниз и по диагонали при разных поворотах
    камеры и масштабе. Точка этажа следует за курсором в ту же сторону.
    Короткая ПКМ по модели задаёт цель, перетаскивание её не переключает.
40. Два раннера с разными цветами пользователей: их модели и программы имеют
    соответствующие акценты и кольца. Обычные программы стоят возле владельца,
    а развёрнутый Black ICE остаётся на своём игровом этаже, не рядом с хозяином.
41. Сменить цель раннера, привязать ICE к другой цели. Модели поворачиваются
    лицом к видимой цели. После Slide лёд перестаёт следить за сбежавшим.
    Наведение на модель не меняет её координаты или поворот.
42. Sword, Banhammer, Hellbolt, Vrizzbolt, Deck KRASH, Nervescrub, Poison
    Flatline, Superglue: завершить атаку и защиту. При попадании эффект идёт
    к поверхности исходной цели; при промахе нет вспышки попадания. FX не
    наносит урон сам. При ручной защите анимация ждёт ответа защищающегося.
    Без разрешённой пары бросков GM-анимация результата не выдумывается.
